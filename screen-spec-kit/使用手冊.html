screen-spec-kit 0.13.1

畫面規格與示意圖工具組｜使用手冊

讓 AI 依同一套設計規範，訪談需求並產出網站地圖、頁面示意圖、跨頁流程、系統架構圖與規格文件；任何 AI 工具都能接手同一個專案。

1這是什麼

screen-spec-kit 把「捐款平台示意圖」這套做法整理成可重複使用的工具組。用它建立的每個專案都會產出相同功能的文件網站：

index.html 文件網站網站地圖、點擊放大的燈箱（示意圖、流程、開發說明、SA 規格）、流程位置、文件完整度。雙擊就能開，不需要伺服器。
Markdown 規格每頁的說明、欄位、畫面文字、開發說明、SA 規格、API 規格，以及全站共用規則與待確認事項。
SVG 示意圖依元件與品牌配色組出畫面初稿，之後可局部修改；選單由工具統一更新。
流程與架構圖PlantUML 跨頁流程、系統情境圖與功能架構圖，一律用本機渲染。

不綁定 AI：設計規範是一般的 Markdown 檔，放在每個專案的 規範/ 資料夾。Claude、Codex、Gemini、Copilot、Cursor 等讀的都是同一份，同一個專案也可以中途換 AI 接續。

2事前準備

最快的方式：照入門頁 快速開始 做兩步：先在 PowerShell（Windows）或「終端機」（macOS）貼一行指令執行安裝腳本，再在空資料夾開啟 Claude Code 或 Codex 貼上提示詞。安裝腳本只用免安裝版軟體，放在家目錄的 NewebDoc，不需要系統管理員、winget、Homebrew 或 Git。

項目用途說明
Python 3.9 以上執行同步與檢查工具安裝腳本會沿用電腦已有的 Python，沒有就下載免安裝版到 ~/NewebDoc/env/python。Windows 上指令中的 python3 改用 python，並需 PYTHONUTF8=1（腳本會設定）。
PlantUML（本機）渲染流程圖、架構圖安裝腳本下載官方免安裝版到 ~/NewebDoc/env/plantuml：Windows x64 與 Apple 晶片用 native 版（不需要 Java、Graphviz）；ARM64 Windows 與 Intel Mac 用 jar 版，另下載免安裝版 Java 到 ~/NewebDoc/env/java。不要使用會把原稿送到線上伺服器的渲染方式。
rsvg-convert（選用）產生縮小預覽圖檢查版面brew install librsvg；預覽圖只放暫存資料夾，不放進專案。
任一 AI 工具訪談、修改、產出Claude Code、Codex、Gemini CLI、GitHub Copilot、Cursor 等，能讀寫專案資料夾、能執行指令即可。
screen-spec-kit 資料夾範本、引擎、共用規範安裝腳本下載到家目錄 ~/NewebDoc/screen-spec-kit，所有專案共用，建立與升級專案時會用到。

檢查與更新

在工具組資料夾執行 python3 tools/doctor.py，確認最後一行是「環境：全部就緒」；缺少時會印出安裝腳本的指令。

之後要拿新版，重新執行安裝腳本，或執行 python3 ~/NewebDoc/screen-spec-kit/tools/update_kit.py，再依「升級專案」更新各專案。用 Git 的人也可以部分下載 NewebDoc 的 screen-spec-kit/（update_kit.py 會改用 git pull）：

git clone --filter=blob:none --sparse https://github.com/lingogo2025/NewebDoc.git ~/NewebDoc
git -C ~/NewebDoc sparse-checkout set screen-spec-kit

工具組（screen-spec-kit）

每個專案

檔案放什麼可以手改嗎

畫面與流程文字規格.md、網站地圖.md規格與網站地圖本文，是所有圖與網頁的基準。可以（透過 AI 依規範修改）

scripts/、assets/*.js引擎工具與工具產生的資料。不行

4怎麼讓 AI 引用（重點）

不論用哪套 AI，都是在專案資料夾開啟 AI。AI 會先讀入口檔，入口檔再把它導到 規範/、專案規則.md 與 project.json。

入口檔→規範/README.md→規範/修改專案.md 或 新專案.md→專案規則.md→project.json
AI 工具讀的入口檔怎麼開始
Claude CodeCLAUDE.md在專案資料夾開啟即可。也可以安裝 plugin，使用 spec-change、spec-new 兩個 skill（選用，見下方）。
Codex、Cursor 等AGENTS.md在專案資料夾開啟即可。
Gemini CLIGEMINI.md在專案資料夾開啟即可。
GitHub Copilot.github/copilot-instructions.md在 VS Code 開啟專案資料夾。
其他 AI／網頁版對話無自動讀取第一句話請它：「先讀 AGENTS.md，再依它的指示工作」；網頁版不能讀檔時，把 規範/README.md、規範/修改專案.md 與 專案規則.md 一起提供給它。

大部分工具會自動讀入口檔；如果 AI 的回答看起來沒照規範（例如沒先查影響範圍就直接改檔），請它「先讀 AGENTS.md 與 規範/README.md」再繼續。

開場說法範例

  • 修改：「我要在會員中心新增一頁『捐款收據下載』，先依規範查影響範圍給我確認。」
  • 新專案：「依 規範/新專案.md，幫我建立一個新的活動報名平台專案。」
  • 接續：「先跑 interview_status.py，從下一個未完成的訪談階段繼續。」

Claude Code plugin（選用）

不安裝也完全能用。安裝後 Claude Code 多兩個 skill 入口，內容一樣只是指向 規範/：

claude plugin marketplace add ~/NewebDoc/screen-spec-kit
claude plugin install screen-spec-kit@screen-spec-kit

先依「事前準備」下載工具組。之後 git pull 取得新版時，以 claude plugin marketplace update screen-spec-kit 更新 plugin。

5建立新專案

步驟 1：建立空白專案

在 screen-spec-kit 資料夾執行（新資料夾必須不存在或是空的）：

python3 tools/init_project.py "<新專案資料夾>" --name "<專案名稱>"

會建立範本、複製引擎與 規範/、產生四個入口檔並渲染架構圖骨架；最後顯示 check.py 結果，應為 0 錯誤。

步驟 2：選模式

在新專案資料夾開啟 AI，用幾句話描述主題，例如「我要建立一個電子發票加值服務平台」。AI 會問你要走哪種模式：

  • 全自動（案子初期建議）：AI 一次問最多 10 題（主要使用者、區域、核心功能、規模、後台角色、外部系統、對外 API、主色、舊系統、特殊規則），每題第一個選項是 AI 建議並附理由，你可以回「全部照建議」或只改幾題。之後不再提問，直接跑完。
  • 階段式：12 個階段一題一題問，每階段回放確認後才寫入（見步驟 3 的表）。

全自動模式下，AI 寫一份起稿描述，執行：

python3 scripts/draft_apply.py <起稿描述.json>

幾秒內跑完 12 個階段的第一輪資料：網站地圖、每頁示意圖與待確認事項、跨頁流程、系統情境圖與功能架構圖、全站共用規則預設值、API 待確認骨架、舊系統移轉與可能涉及的法規領域，並跑完整檢查。打開 index.html 就能看到全貌。

  • AI 依產業常識推測的內容都標「〔AI 起稿・第 n 階段：待審閱〕」，示意圖上也有「AI 起稿」提醒框。
  • API 欄位、金流、法規、商業政策不推測，只列在「尚待確認」。
  • 起稿只用於剛建立的專案；已有內容的專案不重跑。

步驟 3：逐階段審閱（全自動之後）或訪談（階段式）

起稿後，AI 依下表一階段一階段把初稿攤給你看，你只要回答保留、修改或刪除，確認後才拿掉標記。沒有起稿、從空白開始時，AI 改成一次問一個主題、提供選擇題（第一個是建議答案），回放摘要讓你確認後才寫入。答不出來的項目會標「待確認」，不會自行補上。

階段內容階段內容
1專案概要、品牌與主色、回答語言7跨頁流程
2使用者與角色8外部系統
3業務規則與用語限制9對外 API
4區域（前台、後台…）與各區版型10全站共用規則
5頁面清單與共用選單11逐頁細節（可分次）
6業務模組12選填：舊系統移轉、相關法規

隨時可以查看進度（未完成、待審閱、完成）；中斷後換一個 AI 也能從這裡接續：

python3 scripts/interview_status.py

第 4、5 階段（區域、頁面清單）完成前不畫 SVG、不建流程，因為頁面 ID 還沒確定。

6修改既有專案

直接用一般話描述要改什麼，AI 會依 規範/修改專案.md 的標準流程進行：

查影響範圍→回報並請你確認→先改 Markdown→局部改圖與網頁→寫更新紀錄→同步與檢查
  • 你同意之前，AI 不會改檔；需求不明確或和規則衝突時，它會先問。
  • 新增頁面時，會用元件組出 SVG 初稿；之後的修改都是局部編輯，不重畫整張。
  • 每次修改最後都會跑 check.py，並回報錯誤數、提醒與仍待確認的事項。

想自己看看文件網站，雙擊專案的 index.html 即可。

7升級專案

工具組改版後，先重新執行安裝腳本（或 update_kit.py）取得新版，專案的 check.py 就會提醒「plugin 有新版」。先預覽會變更哪些檔案：

python3 tools/upgrade_project.py "<專案資料夾>" --dry-run

確認後正式升級：

python3 tools/upgrade_project.py "<專案資料夾>"
  • 升級前會自動備份到專案的 .engine_backup/。
  • 只替換 scripts/、規範/ 與 index.html 的引擎部分，並重新產生入口檔；規格、網站地圖、SVG、流程、架構圖都不會動。
  • 舊版專案（規則還寫在 AGENTS.md）會自動把它改名為 專案規則.md，請再刪掉裡面已移到 規範/ 的通用段落。

8規則要寫在哪裡

想加的規則寫在例子
每個專案都適用的設計規範、寫法、流程示範專案的 規範/，再同步到工具組流程圖的配色原則、SA 規格的兩層寫法
只適用某個專案的規則該專案的 專案規則.md捐款小物不得出現售價、某區只列 B 系列頁面
專案設定值project.json品牌主色、區域與頁面 ID 字首、禁用詞
任何規則不要寫進 AGENTS.md、CLAUDE.md 等入口檔入口檔會被工具重新產生，寫了會被覆蓋

分不清是通用還是專案專屬時，AI 會先問：「這條規則以後每個案子都適用，還是只有這個案子？」

9維護者：示範專案同步

捐款平台專案是示範專案，也是工具與共用規範的來源（project.json › kit.engine_source）。它還在調整中，工具組跟著同步：

  1. 在示範專案修改 規範/、scripts/ 或 index.html 的引擎部分。
  2. check.py 會提醒與工具組不一致。
  3. 在示範專案資料夾執行同步：
python3 ../screen-spec-kit/tools/sync_kit.py .

同步會先跑示範專案的檢查（有錯就停止）、匯出到工具組、版本加一，並建一個空白專案自我測試；最後在工具組 README.md「更新紀錄」寫一行。只改了範本（template/）時加 --bump。

4. 把工具組資料夾的內容手動上傳到 GitHub NewebDoc repo 的 screen-spec-kit/（不要上傳 .DS_Store、.bin/、__pycache__/），同事 git pull 就會拿到新版。版本號在看得見的 VERSION 檔，下載清單 FILES.txt 由同步工具自動產生，兩者都要上傳；.claude-plugin/ 只有安裝 Claude Code plugin 時才需要，網頁上傳常會略過以「.」開頭的資料夾，要用 plugin 時另外上傳。

工具組裡的 規範/ 是匯出的複本，不要直接改；其他專案的 規範/ 也是複本，升級時會整份替換。

10指令速查

專案工具都在專案根目錄執行（python3 scripts/<工具>）。平常由 AI 執行，這裡列出方便查閱。

工具用途
check.py一致性檢查（只讀）；每次修改最後都要跑
impact.py <ID 或關鍵字>查影響範圍（只讀）
section.py <ID 或章節>只讀規格中的單一段落
interview_status.py新專案訪談進度（只讀）
page_stub.py <ID> <名稱>新增頁面的規格段落骨架
mockup.py <描述.json>以元件產生新頁面 SVG 初稿（不覆蓋既有檔）
sync_screen_text.py <ID…>把 SVG 可見文字同步到規格
index_build.py由網站地圖.md 產生 index.html 網站地圖、區域設定與主色
nav.py依共用選單表批次更新各頁選單
flow_sync.py更新流程圖例與網頁流程資料（之後以本機 plantuml -tsvg 渲染）
svg_bundle.py、dev_notes.py、inventory.py重產燈箱用的資料檔與文件完整度
ai_entry.py重產四個 AI 入口檔

工具組的工具在 screen-spec-kit/tools/：doctor.py（環境檢查）、update_kit.py（更新工具組）、init_project.py（建立）、upgrade_project.py（升級）、sync_kit.py（示範專案同步）。

11常見問題

check.py 出現「錯誤」或「提醒」怎麼辦？

錯誤要修正，訊息後面通常附了要執行的指令；提醒不擋流程，AI 會回報給你決定。

可以中途換另一套 AI 嗎？

可以。所有規範、進度與待確認事項都在專案檔案裡，新的 AI 從入口檔讀起就能接續；新專案訪談請它先跑 interview_status.py。

AI 說某個 API、金流或法規細節「待確認」？

這是規範要求：這些領域的未知內容不能由 AI 自行補成規格，會列在規格「尚待確認」，等你或相關人員提供。

同事 clone 的位置跟我不一樣，會有問題嗎？

統一放在家目錄 ~/NewebDoc/screen-spec-kit 就不會：專案的 project.json › kit.path 記的是 ~/NewebDoc/screen-spec-kit，每台電腦都找得到。放在別處也能用（每個專案都有自己的 規範/ 與 scripts/ 複本），只是 check.py 不會提醒有新版，修改 kit.path 即可。

需要 PNG 圖檔嗎？

專案只保留 SVG。需要點陣圖時再請 AI 另外輸出，不放進專案。

可以直接手改 index.html 或 SVG 的選單嗎？

index.html 只改內容區；選單改 網站地圖.md 的「共用選單」表，再由 nav.py 更新所有頁面。手改的部分會在下次產生時被覆蓋。
