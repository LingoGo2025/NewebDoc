# 跨頁流程：連動規則與流程圖設計規範（通用）

## 頁面與流程連動（每次必做）

新增、刪除、更名、搬移頁面或調整頁面功能／文案時，先以 `impact.py` 列出相關流程，逐一確認並一併修改，不可只改頁面不管流程。

- `flows/*.puml` 開頭 `@pages` 須包含所有相關頁面，且不含已不相關或已刪除的頁面；新增頁面若屬於某流程，須補進該流程。
- 有兩個以上頁面的流程必須有 `@order`（寫法見規格「流程頁面順序」：逗號分先後、`|` 為並列），其頁面集合須與 `@pages` 相同。新增頁面時同步補進 `@pages` 與 `@order`。
- 流程圖上方的「對應頁面」圖例由 `@order`（無則 `@pages`）產生，不手動編輯。參與者名稱或關鍵步驟仍可自行加註頁面 ID，只作說明，不需要可點選。
- 頁面功能或步驟改變時，流程的訊息步驟、判斷分支與 `@summary` 須同步修改，並更新規格對應流程段落（頁面清單、流程摘要、「流程頁面順序」表）。
- 流程之間的跨頁關聯（頁面說明中的「對應流程」連結、`index.html` 燈箱的相關流程）須與流程頁面清單一致。
- `check.py` 自動檢查頁面清單、標題、`@order`、圖例與 SVG 是否過期；流程步驟內容是否符合新頁面功能無法自動檢查，須人工核對，並在更新紀錄寫明已核對的流程。

PUML 檔頭格式：

```
' @title 流程名稱
' @pages C21,A14,A15
' @order C21,A14|A15
' @summary 一句話摘要
@startuml
...
```

PUML 沒有 `title` 行時，`flow_sync.py` 會依 `@title` 補上（頁面圖例接在 `title` 之後）。

改完：`python3 scripts/flow_sync.py` → 本機 `plantuml -tsvg flows/<key>.puml` → `python3 scripts/svg_bundle.py`。

## 流程圖設計規範（`flows/*.puml` 循序圖）

- 每張流程圖都要上色，但只為「參與者」與群組／備註上色，訊息箭頭不逐條指定顏色；配色淡雅，讓文字與主流程為主。架構圖另有一套較飽和的配色（見 `architecture.md`），兩套色碼不混用。
- 線條清晰優先（低解析度螢幕也要看得清楚）：訊息箭頭深綠灰 `#2F4A44`、粗 1.6；回傳箭頭中灰 `#7C8F88` 虛線；生命線（參與者下方的垂直虛線）`#5E7770` 粗 1.4（粗細要用 `<style> sequenceDiagram { lifeLine { LineThickness } }` 設定，skinparam 無效）；參與者框線 1.6；群組框 `#6F9484` 粗 1.4；訊息文字 13 級。不要再調淡或調細。
- 全圖加淺灰外框（`DiagramBorderColor #C9D3CF`、粗 2），底色維持白色。
- 參與者依規格「系統架構 › 流程圖參與者類別」表上色：每個入口區域一個類別，另有跨區、API、平台服務、外部系統、資料（`database` 一律歸此）等類別；實際類別與顏色以專案規格表為準。使用者（actor）與畫面（participant）同區域同色，以圖形區分人和畫面。
- 顏色不手寫在 PUML：宣告參與者只寫 `participant "名稱" as 代號`（名稱沿用「統一名稱」表），`flow_sync.py` 依類別表加上 `<<類別代號>>` 並在 `@startuml` 下方產生 `' [style:begin]`～`' [style:end]` 樣式區塊（字型、標題品牌綠、群組淡綠、備註淡橘、隱藏類別標籤）；回傳訊息寫 `-->`，由工具改為灰色 `-[#7C8F88]->` 以突顯主流程。
- 不用 `!theme`；新參與者先加進類別表再執行 `flow_sync.py`，接著本機 `plantuml -tsvg` 渲染與 `svg_bundle.py`。
- 類別表的顏色與架構圖圖例分開維護；改類別配色時只改表，再執行 `flow_sync.py` 並重新渲染全部流程。
- 流程圖上方的「對應頁面」legend 是頁面清單，不是色彩圖例，照舊保留在圖內。
- `check.py` 檢查：不用 `!theme`、樣式區塊與類別表同步、每個參與者都列在類別表。
