# index.html：燈箱、首頁區塊、完整度與文件責任（通用）

## 燈箱

- 圖片工具列在頁籤列右側（圖片右上方），下載 SVG 只放這裡，右側說明欄不放下載。示意圖：拖曳／編輯、縮放、重設、下載 SVG；流程說明一次顯示一張，多流程用下拉選單切換，另加「複製語法」。
- 畫面說明下方的獨立區塊「流程位置」永遠展開，依 `@order` 每個流程以兩行呈現：流程名稱＋步數 n/N，及鏈條「上一步 → ● 本頁 → 下一步」（不分區域，僅後台頁面標註區域；起訖不畫箭頭、不寫起點／終點；並列頁面以「｜」同格）；單頁流程不顯示。
- 並列頁面與既有類似頁面列在「相關頁面」；跨區相鄰頁面依方向列在「管理頁面」（往後台）或「結果頁面」（往前台）；區塊沒有內容時隱藏。
- 區域以頁面 ID 字首判斷，前後方向依 `project.json › ids.page_prefixes` 的順序（前台在前、後台在後）；「流程位置」只為 `regions` 中標 `backend: true` 的區域標註區域名稱。這些設定由 `index_build.py` 寫進 index.html 的 `#project-config`，不手改腳本。流程若納入 API 頁面（ID 為 API 字首＋數字），須先調整判斷方式。
- API 燈箱（頁面 ID 為 API 字首＋數字）：頁籤為「流程圖／傳送欄位／回傳欄位／加解密方式／開發說明」（不顯示流程說明、SA 規格）；回傳欄位依 `回傳欄位｜…` 小節分段（如 ReturnURL、NotifyURL）；右側標題為「API 說明」，顯示說明、介接資訊表與對應頁面（可點開該頁燈箱並返回）；流程圖有 `flows/<key>.puml` 原稿時工具列多「複製語法」。
- 架構圖燈箱與頁面不同：只有一個「架構圖」頁籤（不顯示流程說明、開發說明、SA 規格）；工具列多「複製語法」（PlantUML 原稿）；右側標題為「圖說明」，先顯示讀圖說明，接著常駐顯示「圖例」（色塊＋意義，取自規格「圖例」表），下方「對照表」預設收合（系統情境圖：使用者、外部系統；功能架構圖：業務模組、共用服務，模組頁面 ID 可點開該頁燈箱並可返回）；不顯示流程位置與相關頁面。
- 讀圖說明、圖例與對照表都取自規格「系統架構」章（`#### 讀圖說明`、`#### 圖例` 表與各表），由 `dev_notes.py` 打包為 `_architecture`，不手改 index.html。讀圖說明維持 2–3 句，只說怎麼看圖（區塊位置、箭頭與虛線意義、圖的限制），不重複表格內容。
- 改這些規則時同步更新本檔、規格「流程頁面順序」與 `index.html`。

## 首頁折疊區塊

- 標題前有導引數字 `<span class="fold-num">n</span>`，由 `index_build.py` 依畫面由上而下自動編號，不手改。目前的區塊見 `專案規則.md`。
- 專案說明卡放在內容區 `<!-- [slot:cards] -->`（網站地圖與外部系統串接之間），專用樣式放 `/* [slot:project-css] */`；架構圖卡片說明、外部系統引言、移轉計畫、相關法規、頁首、頁尾也各有內容區。內容區以外是引擎，不在專案改。
- 範本固定區塊：系統架構、網站地圖、外部系統串接、舊系統移轉計畫（選填）、相關法規（選填）；專案可另加說明卡（例如品牌標誌說明）。

**系統架構區塊**：放在網站地圖上方，預設收合（`<details>` 不加 `open`）；兩張架構圖以縮圖卡片呈現（連結帶 `data-arch="<檔名>"`），卡片說明中的模組數量須與功能架構圖一致。

**外部系統串接區塊（`#external-systems`）**：預設收合，內容由 index.html 腳本讀取 `dev_notes.js` 的 `_architecture.tables["外部系統"]`（各分組標題的標記與說明讀「外部系統需求類別」表，表內須列出所有需求類別，`check.py` 檢查）（規格「系統架構 › 外部系統」表）依「需求類別」欄分組顯示（系統需求：平台功能運作所需；營運需求：測試系統、內部文件管理系統等開發與營運輔助），不在 HTML 手寫系統清單。新增或修改外部系統時只改規格表（每列須填需求類別），再執行 `dev_notes.py`；並依 `architecture.md`「頁面與架構連動」同步系統情境圖。營運需求系統尚未提供 API 前，介接一律標待確認。

**舊系統移轉計畫區塊（`#migration-plan`）**：整區選填，預設收合；未填時只標出位置（「選填・待補」），文字版在規格「舊系統移轉計畫（選填）」章（錨點 `migration-plan`）。內容由設計者提供後才寫，AI 不自行補；補內容時先改規格章節再改 index.html 區塊。

**相關法規區塊（`#regulations`）**：整區選填，預設收合；未填時只標出位置（「選填・待補」），文字版在規格「相關法規（選填）」章（錨點 `regulations`）。法規名稱、條文與適用範圍由設計者提供後才寫，AI 不自行補（依 `workflow.md`「內容維護」第 8 條，法規未知內容標待確認）；補內容時先改規格章節再改 index.html 區塊。

## 文件內容與完整度（每次必做）

頁首右上角按鈕開啟燈箱，列出本文件包含的資料種類（頁面、流程、架構與規則、待確認）與各自的完整度。

- 數字全部由 `scripts/inventory.py` 從規格、網站地圖、`screens/`、`flows/`、`architecture/` 自動計算，產生 `assets/inventory.js`，不手改；任何修改（含更新紀錄）後都要重新執行，`check.py` 在資料過期或 index.html 缺少按鈕、燈箱、載入時報錯。
- 完整度只計算資料是否存在與是否標示待確認，不代表內容已審核；狀態分完整、部分、待補、選填（設計者補充）、追蹤中（尚待確認事項）。
- 新增資料種類（新的規格章節、圖種、產出檔）或改變計算方式時，在 `inventory.py` 的 `build_data()` 登記一列，並同步本節。各列說明若需專案用語，寫在 `project.json › inventory_desc`。
- 首頁每個折疊區塊都要在完整度有對應列：系統架構→「系統架構圖」、網站地圖→「網站地圖」、外部系統串接→「外部系統串接」（完整度只計外部系統表狀態未標示待確認者）、舊系統移轉計畫→「舊系統移轉計畫」（選填）、相關法規→「相關法規」（選填）；說明卡不計。新增首頁區塊時同步登記，並確認 `questioning.md` 第 3 節有訪談階段會問到這個區塊。
- 選填章節除狀態／用途／首頁對應說明外有內容即算已填。

## 文件責任

- 網站地圖 Markdown：各區域（`project.json › regions`）、功能節點、頁面按鈕、範圍及交叉參照；「共用選單」表是側欄與頂部導覽的基準。index.html 的網站地圖區塊由 `index_build.py` 依本檔產生，格式見 `workflow.md`「網站地圖寫法」。
- 規格 Markdown：每頁說明、SVG 可見文字、系統架構（含外部系統表與需求類別）、API 流程、跨頁流程、流程頁面順序、舊系統移轉計畫（選填）、相關法規（選填）及未決事項。
- `assets/`：只保留目前使用中的正式品牌 SVG，以及工具產生的 `svg_sources.js`（`svg_bundle.py`）、`dev_notes.js`（`dev_notes.py`）、`inventory.js`（`inventory.py`），三者不手改。
- `architecture/`：系統情境圖與功能架構圖的 PlantUML 原稿與 SVG，文字版在規格「系統架構」章。
- `index.html` 與 `screens/`、`flows/`：供內部溝通的首頁折疊區塊、SVG 預覽、流程圖；需與 Markdown 保持一致。
- `scripts/`：`interview_status.py`（新專案訪談進度，依「〔待訪談第 n 階段〕」與「〔AI 起稿・第 n 階段〕」標記判斷）、`draft_apply.py`（全自動起稿：依起稿描述 JSON 一次產生新專案初稿）、`ask.py`（點選式問卷：把要問使用者的問題做成網頁，填完複製答案貼回；不讀專案設定，建立專案前也能用）、`page_stub.py`（新增頁面的規格段落骨架）、`mockup.py`（依頁面描述以元件組合產生新頁面 SVG 初稿，配色讀 `theme`）、`index_build.py`（依網站地圖 Markdown 與 `project.json` 產生 index.html 網站地圖區塊、`#project-config` 與主色 `#project-theme`；`--check` 只檢查）、`impact.py`（影響範圍，含所屬架構模組）、`section.py`（讀單段規格）、`nav.py`（共用選單批次更新）、`check.py`（一致性檢查）、`sync_screen_text.py`（SVG 文字同步到規格）、`flow_sync.py`（由 `@order` 產生流程圖頁面圖例、依參與者類別表產生樣式區塊，並把流程資料寫回 index.html；`--check` 只檢查）、`svg_bundle.py`（把頁面、流程與架構圖 SVG 打包成 `assets/svg_sources.js` 供燈箱選取文字；`--check` 只檢查）、`dev_notes.py`（把規格各頁「開發說明」、SA 規格與各 API 的「API 規格」打包成 `assets/dev_notes.js`；`--check` 只檢查）、`inventory.py`（統計文件資料種類與完整度，產生 `assets/inventory.js`；`--check` 只檢查）；`_common.py` 為共用解析函式，並讀取 `project.json`。各檔開頭有用法說明。
- `project.json`：專案專屬設定（檔名、頁面 ID 規則、網站地圖區域與後台標記、index 欄位排列、品牌配色 `theme`、各區版型 `mockup`、標誌 `brand`、架構圖、用語檢查、完整度說明用語），供 `scripts/` 讀取。
- `專案規則.md`：只寫專案專屬規則（區域歸屬、業務規則、品牌素材、配色對照、目前狀態），通用規則在 `規範/`；AI 入口檔（AGENTS.md、CLAUDE.md 等）只指向這兩處，不寫規則。
