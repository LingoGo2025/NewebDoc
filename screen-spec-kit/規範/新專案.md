# 從零建立新專案

取得需求、寫進範本，最後產出與既有專案相同結構與功能的文件網站。有兩種起點：**快速起稿**（案子初期、需求還模糊時建議用）先由 AI 依幾句話產生整案初稿，再逐階段審閱；**逐階段訪談**從空白開始一題一題問。提問方式與通用維護規則同 `修改專案.md`。

## 開始前

1. 讀本資料夾的 `questioning.md`（第 1 節提問原則、第 3 節訪談階段）與 `stages.md`（各階段寫到哪裡、怎麼寫、跑什麼工具）。
2. 用到時再讀：`workflow.md`「網站地圖寫法」、`mockup.md`（SVG 初稿）、`flows.md`（流程）、`architecture.md`（架構圖）、`spec-writing.md`（開發說明、SA、API）。
3. 建立專案要用 screen-spec-kit plugin 的 `tools/`、`template/`、`engine/`：本資料夾在 plugin 內時就是上一層；在既有專案內時，plugin 位置見該專案 `project.json › kit.path`；其他情況預設在家目錄 `~/NewebDoc/screen-spec-kit`（Windows 為 `%USERPROFILE%\NewebDoc\screen-spec-kit`；GitHub `lingogo2025/NewebDoc` 的 `screen-spec-kit/`）。都找不到時依 plugin 的 `SETUP.md` 從 GitHub 取得，或問使用者。環境不確定時先執行 `python3 <plugin>/tools/doctor.py`（Windows 用 `python`），依它列出的指令補齊軟體。

## 步驟

1. **建立專案**：問專案名稱與要放的資料夾（必須是新資料夾或空資料夾）。確認後執行：
   `python3 <plugin>/tools/init_project.py "<資料夾>" --name "<專案名稱>"`，結果應為 `check.py` 0 錯誤。之後所有指令都在專案根目錄執行。
2. **選起點**：問使用者要「快速起稿」還是「逐階段訪談」。使用者只給了幾句描述、或說還在初期時，建議快速起稿（第 3 步）；需求已經很清楚、或想一步步來時，走逐階段訪談（第 5 步）。
3. **快速起稿**：
   1. 請使用者用幾句話描述系統（例如「電子發票加值服務平台」）。再**一次問完**最多 4 題選擇題：主要使用者或客戶是誰、需要哪些區域（前台、會員中心、後台、對外 API）、品牌主色（可略過）、已知要串接的外部系統。使用者說「直接起稿」就全部用預設。
   2. 依產業常識寫**起稿描述**（JSON，放暫存目錄，不進專案；格式見 `python3 scripts/draft_apply.py --example`）：專案說明與一句話副標、角色、區域與節點、頁面（每頁 `id`、`name`、`desc`、`kind`、`module`，可加 `fields`／`columns`／`items`）、業務模組、共用服務、外部系統、主要跨頁流程（3–8 條，步驟寫「甲 -> 乙 : 說明」）、對外 API、尚待確認。規模：每區 2–5 個節點、全案約 15–40 頁，寧可少而準。
      - `kind`：`landing`（前台首頁）、`list`（查詢列表）、`form`（填寫表單）、`detail`（明細）、`dashboard`（總覽）、`login`、`text`（說明頁）。
      - **不可推測**：API 欄位、金流、法規、商業政策。這些只寫進 `pending` 與外部系統的狀態「待確認」，頁面與流程寫「（待確認）」，不寫具體數字、期限或條文。
   3. `python3 scripts/draft_apply.py <描述.json> --check` 通過後，去掉 `--check` 寫入。工具會產生網站地圖、規格、架構圖、流程圖與每頁 SVG 初稿，並跑完整檢查；結果應為 0 錯誤（「AI 起稿待審閱」的提醒是正常的）。
   4. 請使用者打開 `index.html` 看整體，說明 AI 推測的內容都標了「AI 起稿」，接著進入**審閱起稿**。
   5. **審閱起稿**：`interview_status.py` 列為「待審閱」的階段依序進行，每個階段一輪：
      1. 把該階段的初稿整理成表格給使用者看（例如第 5 階段：各區節點與頁面清單）。
      2. 請使用者逐項回答保留、修改或刪除，也可以補充新項目。
      3. 依 `修改專案.md` 的流程修改（頁面改名要同步改 SVG 檔名、規格標題與流程；刪頁面要一併刪 SVG、網站地圖按鈕、模組與流程中的 ID）。
      4. 確認後刪除該階段所有「〔AI 起稿・第 n 階段：待審閱〕」標記，執行工具與 `check.py`，在更新紀錄寫一行。
      5. 頁面 SVG 是依 `kind` 產生的通用初稿：該頁內容確定後，若 SVG 尚未手動調整，可改寫頁面描述後以 `mockup.py --force` 重產；之後一律局部修改。
   6. 所有階段審閱完，就和逐階段訪談一樣進入第 11 階段逐頁細節。
4. **看進度**：`python3 scripts/interview_status.py`，列出 12 個階段的狀態（未完成、待審閱、完成）、尚未填的位置與下一個階段。中斷後再回來也從這裡接續。
5. **逐階段訪談**（依 `questioning.md` 第 1 節原則；每輪一個主題、選擇題優先、敏感領域不給建議答案、答不出來標待確認）：
   1. 提問。
   2. 回放摘要（將寫入的文字＋位置），使用者確認。
   3. 依 `stages.md` 寫入，並把該階段的「〔待訪談第 n 階段…〕」標記換成內容；使用者明確表示沒有或略過時，寫明「無」或略過原因後刪除標記。
   4. 執行該階段列出的工具，最後 `python3 scripts/check.py`（錯誤須修正）。
   5. 在規格與網站地圖的「## 更新紀錄」各加一行，執行 `python3 scripts/inventory.py`。
   6. 回報這階段摘要、累計待確認數量，問要繼續下一階段還是先停。
6. **順序限制**：第 4、5 階段（區域、頁面清單）完成前不畫 SVG、不建流程；第 6 階段要等頁面清單確定。使用者想跳階段可以跳，但要說明限制。
7. **完成**：`interview_status.py` 顯示各階段完成（第 11 階段可逐頁持續進行）後，告知使用者之後的修改依 `規範/修改專案.md`（任何 AI 從專案的入口檔開始即可），並列出仍待確認的事項。

## 不可做

- 不在非空資料夾建立專案，不覆蓋既有專案（既有專案依 `修改專案.md`；要更新引擎用 `tools/upgrade_project.py`）。
- `draft_apply.py` 只用於剛建立、還沒有頁面的專案；已經有內容的專案不重跑起稿。
- 不刪除「AI 起稿」標記，除非使用者已審閱確認該階段。
- 不自行補 API、金流、法規、商業政策的內容；一律標「待確認」並列入規格「尚待確認」。
- 不跳過回放摘要直接寫入；不替使用者決定答案。
- 不改專案的引擎（`scripts/`、index.html 內容區以外）；index.html 只改內容區 `<!-- [slot:…] -->`。
- 不用會把原稿送到線上的渲染方式；只用本機 `plantuml`。預覽圖只放暫存目錄。
- 不手改工具產生的內容（網站地圖 HTML、`#project-config`、`#project-theme`、`assets/*.js`、SVG 的 `<g data-nav>`、PUML 的圖例與樣式區塊）。

## 回報

每階段結束：這階段寫了什麼（檔案與位置）、`check.py` 結果、累計待確認數量、下一個階段。
