# 從零建立新專案

以訪談取得需求，逐階段寫進範本，最後產出與既有專案相同結構與功能的文件網站。提問方式與通用維護規則同 `修改專案.md`。

## 開始前

1. 讀本資料夾的 `questioning.md`（第 1 節提問原則、第 3 節訪談階段）與 `stages.md`（各階段寫到哪裡、怎麼寫、跑什麼工具）。
2. 用到時再讀：`workflow.md`「網站地圖寫法」、`mockup.md`（SVG 初稿）、`flows.md`（流程）、`architecture.md`（架構圖）、`spec-writing.md`（開發說明、SA、API）。
3. 建立專案要用 screen-spec-kit plugin 的 `tools/`、`template/`、`engine/`：本資料夾在 plugin 內時就是上一層；在既有專案內時，plugin 位置見該專案 `project.json › kit.path`；其他情況預設在家目錄 `~/NewebDoc/screen-spec-kit`（Windows 為 `%USERPROFILE%\NewebDoc\screen-spec-kit`；GitHub `lingogo2025/NewebDoc` 的 `screen-spec-kit/`）。都找不到時依 plugin 的 `SETUP.md` 從 GitHub 取得，或問使用者。環境不確定時先執行 `python3 <plugin>/tools/doctor.py`（Windows 用 `python`），依它列出的指令補齊軟體。

## 步驟

1. **建立專案**：問專案名稱與要放的資料夾（必須是新資料夾或空資料夾）。確認後執行：
   `python3 <plugin>/tools/init_project.py "<資料夾>" --name "<專案名稱>"`，結果應為 `check.py` 0 錯誤。之後所有指令都在專案根目錄執行。
2. **看進度**：`python3 scripts/interview_status.py`，列出 12 個階段的狀態、尚未填的位置與下一個階段。中斷後再回來也從這裡接續。
3. **逐階段訪談**（依 `questioning.md` 第 1 節原則；每輪一個主題、選擇題優先、敏感領域不給建議答案、答不出來標待確認）：
   1. 提問。
   2. 回放摘要（將寫入的文字＋位置），使用者確認。
   3. 依 `stages.md` 寫入，並把該階段的「〔待訪談第 n 階段…〕」標記換成內容；使用者明確表示沒有或略過時，寫明「無」或略過原因後刪除標記。
   4. 執行該階段列出的工具，最後 `python3 scripts/check.py`（錯誤須修正）。
   5. 在規格與網站地圖的「## 更新紀錄」各加一行，執行 `python3 scripts/inventory.py`。
   6. 回報這階段摘要、累計待確認數量，問要繼續下一階段還是先停。
4. **順序限制**：第 4、5 階段（區域、頁面清單）完成前不畫 SVG、不建流程；第 6 階段要等頁面清單確定。使用者想跳階段可以跳，但要說明限制。
5. **完成**：`interview_status.py` 顯示各階段完成（第 11 階段可逐頁持續進行）後，告知使用者之後的修改依 `規範/修改專案.md`（任何 AI 從專案的入口檔開始即可），並列出仍待確認的事項。

## 不可做

- 不在非空資料夾建立專案，不覆蓋既有專案（既有專案依 `修改專案.md`；要更新引擎用 `tools/upgrade_project.py`）。
- 不自行補 API、金流、法規、商業政策的內容；一律標「待確認」並列入規格「尚待確認」。
- 不跳過回放摘要直接寫入；不替使用者決定答案。
- 不改專案的引擎（`scripts/`、index.html 內容區以外）；index.html 只改內容區 `<!-- [slot:…] -->`。
- 不用會把原稿送到線上的渲染方式；只用本機 `plantuml`。預覽圖只放暫存目錄。
- 不手改工具產生的內容（網站地圖 HTML、`#project-config`、`#project-theme`、`assets/*.js`、SVG 的 `<g data-nav>`、PUML 的圖例與樣式區塊）。

## 回報

每階段結束：這階段寫了什麼（檔案與位置）、`check.py` 結果、累計待確認數量、下一個階段。
