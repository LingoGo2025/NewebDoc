# 系統架構：連動規則與架構圖設計規範（通用）

系統架構圖（系統情境圖、功能架構圖）放 `architecture/`，不放 `flows/`。文字版在規格「## 系統架構」章。外部系統、模組或共用服務有變時，先改規格「系統架構」章，再改 `architecture/*.puml`，以**本機** `plantuml -tsvg architecture/<key>.puml` 渲染，接著執行 `svg_bundle.py`。index.html 的「系統架構」區塊連結不帶 `data-screen-id`，不計入網站地圖按鈕檢查。

## 頁面與架構連動（每次必做）

以下情況先改規格「系統架構」章，再改 `architecture/` 對應的圖（本機 `plantuml` 渲染後執行 `svg_bundle.py`）。`impact.py <頁面ID>` 會列出該頁所屬模組。

| 情況 | 要改的地方 |
|---|---|
| 新增、刪除頁面，或頁面改歸別的模組 | 「業務模組」表、功能架構圖的模組方塊與入口層頁面範圍 |
| 新增、刪除、更名業務模組或共用服務 | 「業務模組」或「共用服務」表、功能架構圖 |
| 新增外部系統、介接方式改變，或「待確認」定案 | 「外部系統」表（含「需求類別」：系統需求／營運需求）、系統情境圖；首頁「外部系統串接」區塊與完整度自動跟著表，只需重跑 `dev_notes.py`、`inventory.py` |
| 新增使用者類型或角色 | 「使用者」表、系統情境圖 |
| 新增或修改流程 | 參與者沿用「統一名稱」表；需要新名稱時先加進表（新名稱也會成為檢查基準） |
| 新增架構圖 | `project.json › architecture.figures` 登記檔名與圖名，並補讀圖說明與圖例 |

- 圖的畫法或圖例改變時，同步修改「讀圖說明」與「圖例」表。
- 暫時不歸入模組的頁面寫在「業務模組」表下方 `- 暫不歸入模組：<ID>（原因）` 一行。
- `check.py` 自動檢查：每個頁面都歸入模組、表內 ID 存在、功能架構圖的模組與入口層頁面和規格一致、流程參與者不用舊名稱、架構圖 SVG 不比 PUML 舊。外部系統、使用者與系統情境圖的內容無法自動檢查，須人工核對，並在更新紀錄寫明。

## 架構圖設計規範（`architecture/*.puml`）

架構圖與流程圖用兩套配色：架構圖是對外說明的總覽，配色較飽和、豐富；流程圖每頁都會看到，配色淡雅、只區分角色（見 `flows.md`）。兩套色碼不混用。

- 兩張架構圖都必須以色彩表達資訊，不可只用單色：
  - 系統情境圖：顏色表達「入口區域與對應使用者」及「外部系統的介接狀態」（已定、介接待確認、不串接）。
  - 功能架構圖：入口層顏色表達網站地圖區域；業務模組顏色表達閱讀分組；共用服務用中性灰。
  - 各入口區域與業務模組分組的實際配色對照寫在 `專案規則.md` 與規格「系統架構 › 圖例」表。
  - 顏色只是輔助，文字仍須自足：待確認同時用虛框／虛線與「待確認」字樣，不只靠顏色辨識。
- 不套 `!theme`，以 skinparam 統一風格：字型 PingFang TC、文字 `#203F3C`、白底、無陰影、標題品牌綠 `#087E78`、圓角 12、方塊框線 2。
- 線條要在低解析度螢幕也看得清楚：箭頭粗 1.8 以上（系統情境圖 1.8、功能架構圖 2）、顏色用深色（系統情境圖 `#0B7285`），線上文字 13 級；人形 actor 框線 1.8。
- 全圖加淺灰外框（`skinparam DiagramBorderColor #C9D3CF`、`DiagramBorderThickness 2`），讓人看得出圖的範圍。
- 方塊一律以 `#底色;line:框線色` 上色，飽和的中淺底色配鮮明框線，色碼只用規格「系統架構 › 圖例」表列出的顏色；同一意義在兩張圖用同一組顏色。業務模組每組各用一個色相。
- 功能架構圖三層的外框也上色：入口層綠框、業務模組橘框、共用服務灰框，層間箭頭用粗線並與來源層同色。功能架構圖的方塊代號：入口層 `E<n>`、業務模組 `M<n>`（`check.py` 依此比對模組與頁面）。
- 介接「待確認」的外部系統用黃色虛框（`#FFF0B3;line:D4A20A;line.dashed`），其連線用同色虛線；不串接用灰色虛線。
- 營運需求的外部系統（測試系統、內部文件管理系統等）尚未提供 API 前，一律畫成介接待確認的黃色虛框，節點名稱第二行加「營運需求・API 待補」，連線文字標「（待確認）」；API 完成並定案後改為已定的青色方塊。系統需求的節點不另加類別標記。
- 使用者到入口的箭頭用粗線、該入口的框線色；平台對外箭頭用外部系統青色。
- 業務模組的顏色只是閱讀分組，不是正式分類；分組寫在「圖例」表的意義欄，改分組時同步改表與 PUML。
- 圖內不放 `legend`：圖例寫在規格「系統架構 › 圖例」表（圖、底色、框線、意義；框線欄可加「虛線」），由 `dev_notes.py` 打包，燈箱右側常駐顯示。新增或改顏色時先改表再改 PUML。
- `check.py` 檢查：圖內無 legend、每張圖有圖例、圖例色碼都用在圖上、圖上方塊底色都列在圖例。
